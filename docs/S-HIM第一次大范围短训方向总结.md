## 二、核心问题诊断与机理分析

### 1. 为什么 `PopSAN` 在 S-HIM 单阶段框架里效果不如 `LIFActor`？
对照 `graduation/snn/population_actor.py` 源码及 `c1b` vs `c2` 实测日志，根因有四点：
1. **输出端群体解码红利已被 `LIFActor` 完整继承**：`LIFActor` 与 `PopSANActor` 拥有完全相同的末层分组卷积解码器 `nn.Conv1d(actions, actions, population, groups=actions)`；`PopSANActor` 多出来的主要是输入端高斯群体编码器 `PopEncoder` 与 `ticks=5` 二阶突触衰减。
2. **`PopEncoder` 感受野与 `GRSN + SwAV` 多量纲特征严重失配且参数暴涨 10 倍**：`PopEncoder` 默认对 64 维输入每维在 `[-5.0, +5.0]` 铺 10 个 `std=0.387` 的高斯中心（间距 `1.11`），但 `SwAV` 16 维潜变量经过 L2 单位球面归一化（单维幅值仅 `[-0.4, +0.4]`），重力投影与指令也在 `[-1, +1]` 内，导致约 80% 编码神经元中心落在有效区间之外；同时首层权重从 `64×256`（1.6 万参）膨胀到 `640×256`（16.4 万参），在 PPO 噪声梯度下收敛极慢且单轮耗时从 `6.33 s` 增至 `7.33 s`。
3. **窄高斯核放大估计器在线漂移 KL，触发 PPO 限速**：`GRSN` 更新权重或校准统计后，`vel / latent` 微小漂移经窄高斯核产生非线性跳变，导致第 400 轮 `c1b` 的 `aux_update_kl_mean=0.1470`、`commit_kl_p95=0.6890`（`c2` 为 `0.0870 / 0.4663`），将 `lr` 压至 `0.000171`、`actor_rel_update` 跌至 `c2` 的 `1/7`（`0.000186` vs `0.001307`）。
4. **`ticks=5` 量化更粗且后两层脉冲过饱和**：`c1b` 三层发放率达 `[0.213, 0.510, 0.604]`，稀疏性与动态范围均逊于 `c2`（`[0.202, 0.286]`）与 `c3`（`[0.205, 0.307, 0.357]`）。

### 2. 为什么此前 AMP 盲走窄梯频繁侧偏（`lateral_exit` 高达 `10/16~13/16`）？
运动学与 FK 逐帧审计暴露了动作数据的关键错配：
- **旧默认 `a1_trot`（`third_party/amp_motions_a1/trot0..2.txt`，真狗动捕重定向）**：实测是 **`1.40~1.70 m/s` 高速颠跳步态**（`vz_std = 0.27 m/s`，对角相关性仅 `+0.14~+0.34`），更致命的是数据本身自带 **`vy = +0.097 m/s` 侧蟹漂移、`yaw = -0.062 rad/s` 偏航漂移、以及左右前脚 `3.8 cm` 高度不对称（`-0.237 m` vs `-0.275 m`）**，直接把策略带偏出窄梯。
- **跑酷小跳（`third_party/WMP/datasets/mocap_motions/hop1.txt, hop2.txt`）**：四腿同相腾空跳跃（`vz_std = 0.63~0.70 m/s`，腾空率 `20%~31%`，`front = +0.99`），只适用于跨越壕沟跑酷，绝不能混入盲走上楼梯。
- **正确的盲走专家数据（新默认 `a1_diagonal`：`third_party/WMP/datasets/mocap_motions/trot1.txt, trot2.txt`）**：由 A1 普通对角抬腿前进策略录制，`dt = 0.020 s`（50 Hz 严格匹配）、`vx = +0.393 / +0.800 m/s`（正好覆盖 `0.6 m/s` 目标速度）、机身恒稳 `0.28~0.30 m`、**零腾空（`flight = 0.00`）、零弹跳（`vz_std = 0.03 m/s`）**、纯对角交替抬腿（相关性 **`+0.93 / +0.95`**，摆动高抬腿 **`9.5~10.1 cm`**）、左右脚高差仅 `5 mm`、零侧偏（`vy ≈ 0, yaw ≈ 0`）。已通过 `codex` 将 `--amp-motion-set` 默认切换为 `a1_diagonal` 并通过 `34` 项单测验收。

### 3. `NLIF LIF (none)` 属于全脉冲方案吗？
- **突触计算与能耗口径**：`LIFActor (NLIF, none)` 所有核心层间矩阵运算（`layers.1`、`layers.2`、`GRSN` 循环层与 `estimate`）均由 `0/1` 二值脉冲触发（纯稀疏 AC），仅在首层直接编码与最后 `12×pop` 个标量读出存在 MAC。与 `All-Spike` 的唯一区别是末层神经元不设阈值重置，直接对膜电位做泄漏积分平均再经 `readout` 输出连续关节角，几乎不增加能耗却消除了末层 `T=8` 脉冲量化台阶。
- **最严苛全二值口径**：`c3 (All-Spike)` 属于连输出群体也二值脉冲化的“严格全二值脉冲”，`c2 (NLIF)` 属于“全脉冲隐层 + 非脉冲膜电位读出”。两者互为最佳主方案与消融对照。

### 4. 奖励、方差、学习率与 `CaRe-BN` 经验定型
- **奖励定型为 `snn-stair`**：去掉压制脉冲的 `action_rate/smoothness/foot_clearance`，恢复 `base_height_target=0.30`（解决 `0.28 m` 蹲低碰膝盖），放轻高台阶卡滞惩罚（`stumble=-0.1, collision=-0.25, base_height=-0.5`），加强前向与航向追踪（`tracking_lin_vel=3.0, tracking_ang_vel=1.2`）。
- **探索方差保护**：去平滑惩罚后必须配 `--entropy-coef 0.002 --max-action-std 0.55`（否则 `std` 会从 `0.56` 发散到 `1.44`）。
- **学习率上限保护**：必须配 `--desired-kl 0.045 --max-lr 8e-4`（防止无上限时冲至 `0.0029` 摧毁策略，或 `desired_kl` 过紧锁死在 `1e-5`）。
- **跨轮环形 `CaRe-BN`（`--actor-norm care`）**：确实显著降低更新抖动（`ppo_kl_p95: 0.0911 -> 0.0516`），但冷启动慢约 150 轮且发放率升至 `~0.57`；长训优先以 `actor_norm=none`（仅 `GRSN` 用环形 `CaRe-BN`）为主线，视需要作次级消融。

## 三、确认进入长训的核心方向

1. **主推 S-HIM 方向 1（主力冲级 `level 5+`）**：`GRSN (环形 CaRe-BN) + LIFActor (NLIF, actor_norm=none, Rect, ticks=8, widths=256 128) + AMP (a1_diagonal, coef=0.4) + snn-stair`。
2. **备选 / 对照 S-HIM 方向 2（严格全二值脉冲）**：同上，仅切换 `--actor-readout-mode spike`（`All-Spike`）。
3. **同条件 ANN 对照基线**：在 S-HIM 一次性 `5000` 轮内达到 `terrain_level > 5.0` 后，使用**完全相同的 `snn-stair` 奖励、`a1_diagonal` AMP 数据、AMP 权重、地形与优化约束**训练 `HIMLoco + AMP`（`scripts/bench_blind.py himloco --amp`），进行公平迁移效果与能耗对比。
